Cây nhị phân tìm kiếm (BST)

Vẽ đúng cây từ dãy chèn, ghi đủ 6 kiểu duyệt, xóa bằng thế mạng — và viết tay cả loạt hàm đệ quy.

Thắng lợi của bài: từ một dãy chìn bất kỳ, vẽ đúng BST, ghi được cả 6 kiểu duyệt (NLR, LNR, LRN, NRL, RNL, RLN), vẽ lại cây sau khi xóa (thế mạng), và viết tay InsertNode, SearchNode, đếm node / đếm lá / tổng khóa theo điều kiện, chiều cao, in theo mức, EvenMax.

Câu 2 (1.5đ): cho dãy 12 giá trị 40, 50, 4, 30, 45, 60, 20, 10, 15, 3, 90, 70. (a) Vẽ cây BST T1 sau khi thêm lần lượt từ trái sang phải (T1 rỗng ban đầu). (b) Cho biết kết quả duyệt T1 theo thứ tự Right Left Node (RLN). (c) Vẽ lại T1 sau khi xóa lần lượt 60 và 4 sao cho T1 vẫn là BST — nút thay thế được chọn (nếu có) là giá trị nhỏ nhất nhưng lớn hơn giá trị cần xóa.

1. Chèn & tìm: khóa nhỏ qua trái, khóa lớn qua phải

Chèn mỗi khóa: từ gốc đi xuống — khóa mới nhỏ hơn node hiện tại thì rẽ trái, lớn hơn thì rẽ phải, đến chỗ trống thì gắn vào. Mỗi khóa chỉ có một đường đi, nên vẽ nhanh bằng mắt.

Hai hàm nền cho mọi câu code BST — thuộc lòng:

struct TNODE { int key; TNODE *pLeft, *pRight; };
typedef TNODE *TREE;

void InsertNode(TREE &T, int x) {
    if (T == NULL) { T = new TNODE{x, NULL, NULL}; return; }
    if (x < T->key) InsertNode(T->pLeft, x);
    else if (x > T->key) InsertNode(T->pRight, x);
}

TNODE *SearchNode(TREE T, int x) {
    while (T && T->key != x)
        T = (x < T->key) ? T->pLeft : T->pRight;
    return T;   // NULL: không có x
}

Tìm kiếm đi cùng một đường như chèn: mỗi bước loại hẳn một nhánh, nên số bước nhiều nhất bằng chiều cao cây.

2. Sáu thứ tự duyệt — mẹo đọc ngược

Mỗi kiểu duyệt chỉ là một bộ ba chữ: N = node (gốc), L = left (trái), R = right (phải), viết theo đúng thứ tự gọi. Toàn bộ 6 kiểu trên T1:

RLN không phải LNR đọc ngược. Trên T1, LNR đọc ngược cho 90 70 60 50 45 40 30 20 15 10 4 3 — đó là RNL, vẫn khác RLN thật (70 90 60 45 50 …). Chỉ hai đẳng thức đúng là RLN = NLR-đọc-ngược và LRN = NRL-đọc-ngược.

3. Xóa (chỉ cần vẽ tay): lá — 1 con — 2 con

Đề không đòi cài đặt xóa BST — chỉ vẽ. Ba trường hợp:

  1. Node lá: bỏ hẳn (cha trỏ NULL).
  2. Một con: cha nối thẳng xuống con duy nhất của node bị xóa.
  3. Hai con: thay node bằng phần tử thế mạng = nhỏ nhất cây con phải (đúng nguyên văn đề: "giá trị nhỏ nhất nhưng lớn hơn giá trị cần xóa" — đi sang phải một bước rồi rẽ trái đến cùng), rồi xóa node thế mạng ở vị trí cũ. Cách đối xứng (lớn nhất cây con trái) vẫn cho BST đúng nhưng không theo quy ước chấm này.

Kiểm tra bằng NLR (viết rồi đọc ngược cho RLN): sau hai lần xóa, NLR = 40 10 3 30 20 15 50 45 90 70, LNR = 3 10 15 20 30 40 45 50 70 90 — vẫn tăng dần, cây còn đúng BST.

4. Mẫu đệ quy: xử lý node + gọi trái + gọi phải

Gần như mọi hàm "thao tác khác" trên cây là một khuôn duy nhất: if cây rỗng trả giá trị mốc; ngược lại tính node hiện tại + gọi đệ quy trái + gọi đệ quy phải.

int CountNode(TREE T) { return T ? 1 + CountNode(T->pLeft) + CountNode(T->pRight) : 0; }

int CountLeaf(TREE T) {
    if (!T) return 0;
    if (!T->pLeft && !T->pRight) return 1;      // lá: không có con
    return CountLeaf(T->pLeft) + CountLeaf(T->pRight);
}

int SumEven(TREE T) {                            // tổng khóa theo điều kiện: chẵn
    if (!T) return 0;
    return (T->key % 2 == 0 ? T->key : 0) + SumEven(T->pLeft) + SumEven(T->pRight);
}

int Height(TREE T) { return T ? 1 + max(Height(T->pLeft), Height(T->pRight)) : 0; }

void PrintLevel(TREE T, int k) {                 // in các node ở mức k (gốc ở mức 0)
    if (!T) return;
    if (k == 0) { cout << T->key << ' '; return; }
    PrintLevel(T->pLeft, k - 1);
    PrintLevel(T->pRight, k - 1);
}

5. Câu 10 · EvenMax: khai thác thứ tự BST

Câu 10 (0.5đ): viết hàm int EvenMax(TNODE *Root) nhận Root là con trỏ đến gốc của cây nhị phân tìm kiếm, trả lại giá trị key chẵn lớn nhất trong các nút của cây. Cho sẵn struct TNODE { int key; TNODE* pLeft; TNODE* pRight; }; typedef TNODE* TREE;

Không cần duyệt hết cây: duyệt R − N − L (giảm dần) thì key chẵn đầu tiên gặp chính là chẵn lớn nhất. Trả về −1 khi không tìm thấy — an toàn vì −1 là số lẻ, không thể nhầm với một key chẵn thật.

int EvenMax(TNODE *Root) {
    if (Root == NULL) return -1;          // −1 lẻ ⇒ không nhầm với key chẵn
    int r = EvenMax(Root->pRight);        // phải trước: khóa lớn hơn
    if (r != -1) return r;                // đã tìm thấy bên phải
    if (Root->key % 2 == 0) return Root->key;
    return EvenMax(Root->pLeft);          // node này lẻ ⇒ thử bên trái
}

Ví dụ: cây chèn 50, 30, 70, 20, 40, 60, 75 — duyệt RNL: 75 (lẻ) → 70 (chẵn) ⇒ trả về 70. Cây toàn khóa lẻ (5, 3, 9, 7) ⇒ trả về −1.

EvenMax không phải lúc nào cũng là node phải cùng — node phải cùng có thể lẻ (ví dụ trên: phải cùng 75 lẻ, đáp án là cha của nó, 70). Và khi xóa node 2 con (mục 3), đừng lấy nhầm lớn nhất cây con trái — đề chấm theo nhỏ nhất cây con phải.

Luyện tập — tự nhớ lại, đừng cuộn lên

Câu 2a: cây T1 rỗng, chèn lần lượt 40, 50, 4, 30, 45, 60, 20, 10, 15, 3, 90, 70. Vẽ T1 ra giấy.

40 là gốc; 50 > 40 sang phải; 4 < 40 sang trái; 30 > 4 nằm bên phải của 4; 20 < 30, 10 < 20, 15 > 10 treo bên phải của 10; 3 < 4 bên trái của 4; nhánh phải: 45 < 50, 60 > 50, 90 > 60, 70 < 90.

Câu 2c: từ T1, xóa 60 rồi xóa 4. Vẽ lại cây.

60 có đúng 1 con (90) ⇒ cha 50 nối thẳng xuống 90. 4 có 2 con ⇒ thế mạng = nhỏ nhất cây con phải của 4: sang phải tới 30, rẽ trái đến cùng — là 10; đưa 10 lên chỗ 4 rồi bỏ node 10 cũ. NLR kiểm tra: 40 10 3 30 20 15 50 45 90 70 (đối chiếu hình cuối mục 3).

Cây BST chèn lần lượt 50, 30, 70, 20, 40, 60, 75. Chạy tay EvenMax: hàm trả về giá trị nào, và vì sao không phải node phải cùng?

Trả về 70. Theo RNL (giảm dần): 75 (lẻ, bỏ) → 70 (chẵn, dừng). Node phải cùng 75 lẻ nên không được chọn; 70 là cha của nó. Nếu cây toàn khóa lẻ thì kết quả là −1.
