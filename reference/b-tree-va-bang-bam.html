B-Tree & Bảng băm

Hai chương chỉ thi lý thuyết: B-Tree (tạo, xóa, mã giả) và bảng băm (4 phương pháp, quy tắc thêm/xóa/tìm). Mọi cây dưới đây được sinh và kiểm chứng bằng chính bộ mô phỏng tree.js.

1. B-Tree bậc m — điều kiện phải thuộc

Điều kiệnCông thứcm = 3m = 5
Số khóa tối đa / nodem − 124
Số khóa tối thiểu, node ≠ gốc⌈m/2⌉ − 112
Số khóa tối thiểu của gốc111
Node trong có n khóa ⇒n + 1 conmọi node lá cùng mức

Tràn (vượt m − 1 khóa, tức đạt m khóa) → tách (split): khóa đứng giữa (m=3: khóa thứ 2; m=5: khóa thứ 3) đẩy lên cha, phần còn lại chia đôi làm hai node.

2. Chèn (thêm khóa x)

  1. Tìm lá chứa khoảng của x (x > khóa nhỏ nhất ở node trong → đi nhánh con tương ứng, như tìm kiếm B-Tree mục 4).
  2. Chèn x vào lá, giữ thứ tự tăng.
  3. Lá tràn (m khóa) → tách, khóa giữa đẩy lên cha; cha tràn → tách tiếp, lan lên.
  4. Gốc tràn → khóa giữa làm gốc mới, cây cao thêm 1 mức.

Kiểm chứng: chèn 10, 15, …, 80 (bước 5) vào B-Tree bậc 3 → gốc [45], mức 1 [25] [65], mức 2 [15] [35] [55] [75], lá [10] [20] [30] [40] [50] [60] [70] [80] (đề mẫu Câu 5 — đã chạy bằng btInsert).

3. Xóa khóa x — luồng quyết định

  1. x ở node lá: xóa trực tiếp.
  2. x ở node trong: thế mạng = khóa lớn nhất nhỏ hơn x (nằm ở lá phải nhất của cây con con trái của x), rồi xóa khóa thế mạng ở lá.Đề mẫu Câu 6 dùng quy ước này. Nguồn thuật ngữ underflow / redistribution / concatenation: Comer, The Ubiquitous B-Tree, ACM Computing Surveys 1979.
  3. Lá còn ⌈m/2⌉−1 khóa? Đủ → xong. Thiếu → Underflow:
  4. Mượn qua cha (Redistribution): anh em kề dư khóa thì mượn 1 — khóa phân cách của cha xuống node thiếu, khóa biên của anh em lên thay. [giả định của workspace: ưu tiên node liền trước — hỏi lại giảng viên]
  5. Không anh em dư → Catenation: gộp node thiếu + khóa phân cách của cha + node anh em liền trước (ưu tiên liền trước) thành 1 node.
  6. Cha mất khóa → kiểm tra Underflow ở cha, lan lên; gốc còn 0 khóa → con duy nhất lên làm gốc, cây thấp đi 1 mức.

4. Mã giả tìm kiếm & duyệt B-Tree

Tìm kiếm x trong B-Tree bậc m

Tìm kiếm(x, node):
    i = 0
    while i < node.sokhoa and x > node.k[i]: i++
    if i < node.sokhoa and x == node.k[i]:
        return node          // tìm thấy
    if node là lá: return NULL // hết đường
    return Tìm kiếm(x, node.c[i]) // nhánh con i

Duyệt B-Tree

Duyệt(node):
    if node == NULL: return
    for i = 0 .. node.sokhoa - 1:
        Duyệt(node.c[i])      // con trái của k[i]
        in node.k[i]
    Duyệt(node.c[node.sokhoa]) // con phải cùng

Cho tăng dần đúng thứ tự khóa vì mọi khóa con trái < k[i] < con phải.

6. Bảng băm — công thức phải thuộc

Phương phápCông thức dò lần i (i = 0, 1, 2…)Ghi chú
Băm nối kết (separate chaining)h(k) = k mod M, đụng độ → thêm vào danh sách liên kết tại h(k)không dò tuyến
Dò tuyến tính (linear probing)h(k, i) = (h(k) + i) mod Mdò ô kế tiếp, vòng tròn
Dò bậc 2 (quadratic probing)h(k, i) = (h(k) + i²) mod Mbước 1, 4, 9, 16…
Băm kép (double hashing)h(k, i) = (h₁(k) + i·h₂(k)) mod Mđề mẫu: h₁ = k mod 7, h₂ = 7 − (k mod 7)

Hệ số tải (load factor): α = n/M (n khóa, M ô). Đề câu 7 cho α = 0.6: [suy luận — hỏi lại giảng viên] chỉ chèn thêm khi α sau khi chèn ≤ 0.6 — vì vậy 29 và 36 không được chèn (7/11 ≈ 0.64 > 0.6), bảng dừng ở 6 khóa.

Đặt vào DEL đầu tiên gặp (không phải DEL cuối trước Empty) — chỉ được chắc chắn x chưa có khi dò tới Empty hoặc quét hết bảng. Vì sao không để Empty khi xóa: Empty chặn sớm lời dò, các khóa sau nó sẽ "mất tích" — xem OpenDSA — Hashing Deletion (tombstone); mô phỏng trực quan: VisuAlgo — Hash Table.
